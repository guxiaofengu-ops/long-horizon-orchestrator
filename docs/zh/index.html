为耗时工作而生的 Codex Skill

不要再花模型用量盯着进度条。

通过持久化本地状态机运行推理、训练、评估和多轮 Pipeline。Codex 检查启动过程，真正结束当前回合，只在证据需要判断时返回。

Runner 处理确定性工作：进程、超时、产物、重试、租约和状态转换。Codex 仅在显式审查边界、严重失败或最终完成时出现。

01 / 持久化

断线可恢复状态

SQLite WAL、原子 Worker 结果和可续租租约，让替代 Watchdog 在不重复工作的前提下继续运行。

02 / 证据

验证后才算成功

退出码为零只是开始。新鲜文件、JSON 字段、大小和阶段证据必须全部通过。

03 / 有界

有限运行是结构要求

墙钟时间、阶段次数、失败、重试、迭代和日志都有显式上限。

04 / 恢复

官方唤醒路径

向受管理的 Codex 线程排入消息，或恢复持久化 CLI 会话，不把键盘自动化伪装成 API。

05 / 调度

面向真实调度系统

同一份契约可以使用本地独立 Runner、tmux、SLURM 或用户级 systemd。

06 / 控制

完整运维入口

状态、日志、附加、暂停、恢复、检查点批准、取消和权威 JSON 报告。

每个边界都有真实状态。

每次交接都有持久化状态和明确责任方，不存在悄悄留在后台的 Agent。

Codex 修改Pipeline 与契约
启动预检前 N 个进度事件
独立 Worker等待期间零模型调用
判断检查点验证、唤醒、审查
继续推进训练、循环或结束

明确说明能保证什么，也说明不能保证什么。

长程自动化只有在边界清晰时才值得信任。

可以保证

  • 机械等待期间不调用模型
  • 状态转换和尝试证据持久化
  • 重试和资源消耗有明确上限
  • 重复事件不会重复推进
  • 检查点必须经显式审查才能继续

不会虚假承诺

  • 进程退出就等于成功
  • 所有外部 API 都能严格恰好投递一次
  • 无关的原生 TUI 会实时重绘
  • 未审查 Shell 契约是安全的
  • 主机上一定安装了所有调度器
