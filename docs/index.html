Judgment stays intelligent. Waiting becomes infrastructure.

The runner handles deterministic work—processes, timeouts, artifacts, retries, leases, and transitions. Codex appears only at explicit review boundaries, serious failures, or final completion.

01 / PERSIST

Crash-resilient state

SQLite WAL state, atomic worker results, and renewable leases let a replacement watchdog continue without duplicating work.

02 / PROVE

Evidence before success

Exit zero is only the start. Fresh file, JSON-key, size, and custom phase evidence must all validate.

03 / BOUND

Finite by construction

Wall time, phase runs, failures, retries, iterations, and logs all have explicit ceilings.

04 / RESUME

Official wakeup paths

Queue into a managed Codex thread or resume a persisted CLI session—without pretending keyboard automation is an API.

05 / OPERATE

Built for real schedulers

Use a detached local runner, tmux, a SLURM allocation, or a user systemd unit with the same contract.

06 / CONTROL

Operator escape hatches

Status, logs, attach, pause, resume, checkpoint approval, cancel, and an authoritative JSON report.

A loop with real boundaries.

Each handoff has a persisted state and a concrete owner. No invisible agent remains alive in the background.

Honest about what it can—and cannot—guarantee.

Long-running automation becomes trustworthy when its edges are explicit.

It does guarantee

  • No model calls during mechanical waiting
  • Persisted transitions and attempt evidence
  • Bounded retry and resource behavior
  • Duplicate-resistant event handling
  • Explicit review before checkpoint advance

It does not claim

  • That process exit alone means success
  • Exactly-once delivery across every external API
  • Live repainting of an unrelated native TUI
  • Safety for unreviewed shell contracts
  • Availability of schedulers not installed on the host
